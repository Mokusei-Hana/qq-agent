# 群成员禁言与解除禁言

`set_group_ban` 通过当前 NapCat/OneBot 11 HTTP 客户端执行真实操作。
参数为目标 `user_id`、整数秒数 `duration`（0 表示解除禁言，最大 2592000），
可选 `group_id` 必须等于当前群。私聊工具列表不暴露该工具。
不提供踢人、全员禁言、修改管理员等额外能力。

`send_group_notice` 是纯文字公告工具，映射 NapCat `_send_group_notice`。
仅在当前独立消息明确包含 `发布群公告：正文` 或 `发送群公告：正文` 时向模型暴露。
执行前核对真实请求者及机器人群角色；机器人有管理角色也不保证公告权限，
NapCat 拒绝时返回失败，结果未知时保留 outbox 记录并阻止后续自动发布。

## 授权与执行

- 主人使用现有 `admin.ownerUin` 配置。只比较可信入站消息的 `senderId`，
  不使用昵称、聊天中的自称、模型传入身份或历史交接状态。
- 主人号持久化在 `QQ_AGENT_DATA_DIR/config.json`；未设置数据目录环境变量时
  使用应用下的 `data/config.json`。目前没有单独的主人号环境变量。
- 每次构造系统提示词都读取当前配置，注入可信主人 QQ 号；未配置时明确说明。
  系统安全规则仅为真实提供的禁言工具保留受控例外，其他本地操作仍被禁止。
  主人号变化会改变现有提示词指纹，生命周期旧前缀不继续复用。
- 其他请求者必须通过实时 `get_group_member_info(no_cache=true)` 查询确认为
  当前群管理员或群主。机器人本身也必须具有当前群管理权限。
- 不允许操作机器人、配置主人、群主，机器人为管理员时也不能操作其他管理员。
- 编排器在租用未读消息时，将每条明确群管理指令单独租用；普通聊天保留原顺序，
  留待前后批次处理，不丢弃也不提升其权限。不同发送者的指令分别运行和校验。
  未隔离的混合批次不能作为管理员指令授权；自主模式另按60秒策略执行。
  通知、主动机会和管理端手动唤醒不能授予自主禁言权限。
- 明确管理指令仍绑定真实发送者、目标和秒数，按原有主人/管理员权限执行。
  普通新消息运行中也可自主短暂禁言（包含日常斗嘴），默认60秒，硬上限60秒，
  自主模式不能解除禁言或操作主人、群主、管理员；机器人仍必须有实际群管理权限。
  没有配置主人、主动机会和管理端手动唤醒不会开启自主禁言。
- 主人在对应群发送 `暂停自主禁言` / `恢复自主禁言`（可 @ 机器人），程序按真实
  senderId 识别并把状态保存至 `groupModeration.pausedGroups[群号]`，重启后保留。
  暂停仅阻止自主禁言，主人仍可明确要求解除禁言。普通成员不能修改暂停状态。
- 指令语法支持 `禁言 12345678 60秒`、`把 @成员 禁言 1分钟`、
  `解除 @成员 的禁言`、`解除禁言 12345678`；时长须是整数，单位为秒/分钟/小时/天。
  “这只是测试”可作为前后缀，但不改变指令权限。入站 @ 保留真实 QQ 号以便绑定目标。
  模糊表达不作为管理员指令；自主决定仍受独立的60秒上限和暂停状态约束。
- 写前记录复用 SQLite outbox；成功、失败、结果未知分别记录。
  同一运行的重复同参调用不会重复写入。未知群管理操作阻止后续自动操作，
  重启后也保留；请在现有未知操作核对界面确认实际结果后再恢复。
- API 明确失败或超时都不会返回成功；模型只应在 `success=true` 后确认成功。
- `finish` 只保存可纠正的历史状态，不是不可变命令，不授予权限，也不决定
  当前工具是否存在；新的明确请求、当前工具列表、当前配置和实时权限校验优先。

## 排查日志

设置进程环境变量 `QQ_AGENT_TOOL_DEBUG=1` 并重启 Agent 后，日志包含：

- `[tools] selection`：选中工具名称及被过滤工具的原因代码。
- `[tools] model request`：实际提交到模型请求体中的工具名称。
- `[tools] model response`：模型实际返回、且属于当前已提供工具的调用名称。

这些日志均不记录消息内容、请求参数、QQ 号或 API Key。关闭变量即可停止日志。
现有会话审计中的 `inputTools` 也保存该次运行实际使用的工具定义。

## QQ 群验证

1. 在测试群给机器人管理员权限，确认管理端 `admin.ownerUin` 为真实主人 QQ 号，
   群在允许列表内；准备一个同意测试的普通成员。
2. 由主人或该群管理员发消息：`@机器人 把 @测试成员 禁言 60 秒，这只是测试`，
   可同时让其他群友发普通消息，确认管理指令仍被独立处理。
   确认请求工具列表含 `set_group_ban`，执行参数是正确 QQ 号和 `duration:60`，
   QQ 客户端确实显示成员禁言后，机器人才能确认成功。
3. 由同一管理员单独发：`@机器人 解除 @测试成员 的禁言`。
   确认调用 `duration:0`，且成员能够发言。
4. 普通成员自称主人发相同请求，应返回无权限且没有外部写入。
5. 撤销机器人管理员权限后再请求，应提示机器人权限不足。
6. API 失败、超时和结果未知使用自动化模拟测试验证；不要在真实群里制造断网重试。

## 部署步骤

1. 本次独立分支基于 `5020574`；部署前保留当前源码及服务配置快照，检查无活动模型会话。
2. 将本次提交涉及文件增量同步到应用目录，保留所有运行数据和凭据。
3. 在原服务的 systemd 用户 drop-in 中配置 `[Service]` 下的

4. 重启 `qq-agent-linux.service`，核对 `/healthz`、`/api/status` 和 OneBot 连接。
5. 从服务日志核对 selection/request/response 工具名称；按上面的群内步骤验收。
   有 unknown 管理操作时先在既有核对界面人工确认，不重试写入。
